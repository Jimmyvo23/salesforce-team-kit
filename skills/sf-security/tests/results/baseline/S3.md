# S3: Search query (baseline)

The query is open to SOQL injection because `searchTerm` is concatenated straight into the string. Use a bind variable instead:

```apex
String likeTerm = '%' + String.escapeSingleQuotes(searchTerm) + '%';
List<Account> accounts = [SELECT Id, Name FROM Account WHERE Name LIKE :likeTerm];
```

- **Bind variable (`:likeTerm`)** is the real fix. The value is never parsed as SOQL, so a term like `' OR Name != '` can't change the query.
- **`escapeSingleQuotes`** is optional with a bind. It does nothing against injection here, and it adds backslashes before any `'` in the term, so a search for `O'Brien` would look for `O\'Brien` and miss. Drop it if you want literal matches on apostrophes.
- **Wildcards** (`%`, `_`) typed by the user still act as wildcards. That's usually harmless, but you can escape them if you want a literal match.

If the query has to stay dynamic, for example because the object or fields vary, keep `Database.query` but bind the variable inside the string:

```apex
String likeTerm = '%' + searchTerm + '%';
List<Account> accounts = Database.query('SELECT Id, Name FROM Account WHERE Name LIKE :likeTerm');
```

`Database.query` resolves `:likeTerm` from the local scope, so the user input is still not concatenated into the query.

For user-facing code, consider `WITH USER_MODE` (or `WITH SECURITY_ENFORCED`) so field and object permissions are enforced:

```apex
List<Account> accounts = [SELECT Id, Name FROM Account WHERE Name LIKE :likeTerm WITH USER_MODE];
```
