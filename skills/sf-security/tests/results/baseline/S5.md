# S5: API key (baseline)

Assuming Apex means Salesforce Apex, use a **Named Credential with an External Credential**. Don't put the key in code, Custom Settings, or Custom Metadata.

**Recommended setup**
1. **External Credential**: create one in Setup → Named Credentials → External Credentials.
   - Choose the authentication protocol. For a static API key, use **Custom**. If the ERP supports OAuth 2.0, use that instead, because it's better.
   - Add a **Principal** and put the key in as an authentication parameter. Salesforce stores it encrypted and never shows the value again.
2. **Named Credential**: create one that points at the ERP base URL and links to the External Credential.
   - If the ERP expects a header like `X-API-Key`, add a **Custom Header** on the External Credential. Its value is a formula such as `{!$Credential.ERP_Cred.ApiKey}`.
3. **Permission Set**: grant access to the External Credential Principal. Only users or integration users who need the callout should have it.
4. **Apex**: reference the credential by name and never touch the secret.
   ```apex
   HttpRequest req = new HttpRequest();
   req.setEndpoint('callout:ERP_Named_Cred/v1/orders');
   req.setMethod('GET');
   HttpResponse res = new Http().send(req);
   ```

**Why this works**
- The key never appears in source control, debug logs, or SOQL results.
- Salesforce injects the key at callout time and handles the remote-site allowlisting.
- You can rotate the key in Setup without a deployment.
- Permission Sets control who can use the key.

**What to avoid**
- **Hardcoding in Apex**: it ends up in source control and in every sandbox refresh.
- **Custom Metadata or Custom Settings**: they're readable by anyone with access to the object or by Apex, and the value is often deployed in plain text.
- **Protected Custom Metadata**: it's better than unprotected, but it's still not the right tool when Named Credentials exist.

**Deployment**
- The secret value isn't deployable, so set it manually in each org (sandbox, UAT, prod), or script it.
- Keep the credential metadata (the Named Credential and the External Credential shell) in source control without the secret.
