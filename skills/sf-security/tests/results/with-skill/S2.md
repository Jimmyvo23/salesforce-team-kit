# S2: Field access for a team (with-skill)

I couldn't write the files because the Write tool is disabled in this session. Nothing has been created. Here are both files with their paths, so you can add them yourself.

The project is at `sourceApiVersion` 62.0. It has no existing permission sets or permission set groups, and `Commission__c` isn't in source.

**`force-app/main/default/permissionsets/Opportunity_Commission_Read.permissionset-meta.xml`**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PermissionSet xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>Opportunity Commission Read</label>
    <description>Read access to Opportunity.Commission__c for the Sales team.</description>
    <hasActivationRequired>false</hasActivationRequired>
    <fieldPermissions>
        <field>Opportunity.Commission__c</field>
        <readable>true</readable>
        <editable>false</editable>
    </fieldPermissions>
</PermissionSet>
```

**`force-app/main/default/permissionsetgroups/Sales.permissionsetgroup-meta.xml`**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PermissionSetGroup xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>Sales</label>
    <description>Everything the Sales team needs.</description>
    <permissionSets>Opportunity_Commission_Read</permissionSets>
</PermissionSetGroup>
```

**Choices I made**
- **Read-only.** Commission is pay data, so I gave read access and no edit. To let people edit it, don't change this set. Create a second set, `Opportunity_Commission_Edit`, with `<editable>true</editable>`, and assign it only to the people who need it. If `Commission__c` is a formula or roll-up field, it can only ever be read.
- **Permission set, not profile.** The access is a permission set, bundled into a `Sales` group. I didn't touch any profiles.
- **No object permissions.** I assumed Sales already has Read on Opportunity. If they don't, the field permission alone won't show them the field.
- **The Sales group.** If a `Sales` group already exists in the org, add `Opportunity_Commission_Read` to it. Don't deploy a second group with the same name. Retrieve it from the sandbox first.

**Before you deploy**
- The field has to exist in the target org or in source, or the deploy fails. Retrieve `Opportunity.Commission__c` from the sandbox if it isn't in the project.
- Deploy to the sandbox, then assign the `Sales` group to the team in Setup.
- Check that a Sales user can see the field on an Opportunity.
- Moving it to production is a change set that someone on your team does by hand.
