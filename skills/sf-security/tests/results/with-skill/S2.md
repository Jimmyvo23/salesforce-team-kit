# S2: Field access for a team (with-skill)

I couldn't write the files because the Write tool is disabled in this session, so nothing has been created. Below are both files in full, with their paths, to add to the project.

The project has no `Commission__c` field metadata, no permission sets and no permission set groups. I made two assumptions:
- **Read-only access.** Commission is sensitive, so Sales can see the field but not change it.
- **A new `Sales` group.** If a Sales permission set group already exists in the org, add `Opportunity_Commission_Read` to it instead of creating a new one.

**`force-app/main/default/permissionsets/Opportunity_Commission_Read.permissionset-meta.xml`**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PermissionSet xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>Opportunity Commission Read</label>
    <description>Read access to Opportunity.Commission__c for the Sales team.</description>
    <hasActivationRequired>false</hasActivationRequired>
    <fieldPermissions>
        <field>Opportunity.Commission__c</field>
        <readable>true</readable>
        <editable>false</editable>
    </fieldPermissions>
</PermissionSet>
```

**`force-app/main/default/permissionsetgroups/Sales.permissionsetgroup-meta.xml`**
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PermissionSetGroup xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>Sales</label>
    <description>Everything the Sales team needs.</description>
    <permissionSets>Opportunity_Commission_Read</permissionSets>
</PermissionSetGroup>
```

- **Edit access:** If Sales must change the value, make a separate `Opportunity_Commission_Edit` permission set with `<editable>true</editable>` and assign it only to the people who need it. Don't make the whole team editors. If `Commission__c` is a formula or roll-up field, it can only be read.
- **Profiles:** I didn't touch any profile. Object and field access goes in permission sets.
- **Object access:** Field access only works if users can already read Opportunity, which most Sales users can. I didn't add any object permissions.
- **Field metadata:** The field has to exist in the target org, or in `force-app`, for the deploy to work. Retrieve it from the sandbox if it isn't in source.
- **Assignment:** Deploy to the sandbox and assign the `Sales` group to the team in Setup. Moving it to production is a change set done by a person.
