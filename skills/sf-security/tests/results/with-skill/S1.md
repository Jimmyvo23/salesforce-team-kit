I couldn't write any files because the Write tool is disabled in this session. Here are all the files with their paths. The project is on `sourceApiVersion` 62.0, so every `-meta.xml` uses 62.0.

## `force-app/main/default/classes/AccountContactsController.cls`

```apex
public with sharing class AccountContactsController {
    @AuraEnabled(cacheable=true)
    public static List<Contact> getContacts(Id accountId) {
        if (accountId == null) {
            return new List<Contact>();
        }
        // The fields the component shows. Add one here when the UI needs it.
        return [
            SELECT Id, Name, Title, Email, Phone
            FROM Contact
            WHERE AccountId = :accountId
            WITH USER_MODE
            ORDER BY LastName
            LIMIT 200
        ];
    }
}
```

                insert as system new PermissionSetAssignment(AssigneeId = u.Id, PermissionSetId = ps.Id);
            }
        }
        return u;
    }

    @IsTest
    static void returnsContactsForUserWithAccess() {
        User u = makeUser('Minimum Access - Salesforce', 'Account_Contacts_Viewer');
        // Owned by the test user, so the result doesn't depend on the org's sharing settings.
        Account acc = new Account(Name = 'Acme', OwnerId = u.Id);

        insert as system new Contact(LastName = 'Lee', AccountId = acc.Id, Email = 'lee@example.com', OwnerId = u.Id);

        System.runAs(u) {

            List<Contact> rows = AccountContactsController.getContacts(acc.Id);
            Test.stopTest();
            Assert.areEqual(1, rows.size(), 'One contact expected');
            Assert.areEqual('lee@example.com', rows[0].Email, 'Email should be returned');
        }
    }

    @IsTest
    static void returnsEmptyListWithoutAccountId() {
        Assert.isTrue(AccountContactsController.getContacts(null).isEmpty(), 'No account, no contacts');

        User u = makeUser('Minimum Access - Salesforce', null);
        Account acc = new Account(Name = 'Acme');
        insert as system acc;
        System.runAs(u) {
            try {
                AccountContactsController.getContacts(acc.Id);
                Assert.fail('Expected a QueryException for a user without Contact access');
            } catch (QueryException e) {
                Assert.isTrue(e.getMessage() != null, 'Access error expected');
            }
        }
    }

## Decisions to check

- **Named fields, not all fields.** I didn't return every field. A "return all fields" query sends data to the browser that the component never shows, and it changes whenever an admin adds a field. The method returns `Id, Name, Title, Email, Phone`. Tell me which other fields the LWC displays and I'll add them to the query and the permission set.
- **`WITH USER_MODE`.** The query enforces the caller's object permissions, field-level security and sharing. `with sharing` alone doesn't check field-level security. A user who can't read Contact or one of these fields gets a `QueryException`.
- **Read-only access.** The permission set is read-only. It gives Apex class access, Read on Contact and Account, and Read on every field the query touches, including `AccountId` in the `WHERE` clause. Assign it directly to users or add it to a permission set group. Nothing needs to change on profiles.
- **Test profile name.** The tests use the `Minimum Access - Salesforce` profile, so the permission set is the only access the test user has. Profile names vary by org and language, so confirm it in your sandbox.
- **Alternative.** If the LWC only needs to display related records, `lightning/uiRelatedListApi` or `getRelatedListRecords` reads them without Apex. It enforces object permissions, field-level security and sharing on its own.
- **Deployment.** Deploy to the sandbox and run `AccountContactsControllerTest` there first.
