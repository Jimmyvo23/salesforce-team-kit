## Where to store it

Store the key in a **Named Credential backed by an External Credential**. Salesforce keeps the key encrypted. Apex calls `callout:ERP/...` and never sees the key.

Don't put it in any of these:
- **Apex code or constants:** they end up in source control and every sandbox.
- **Custom settings:** they are readable by all profiles, including guest users.
- **Custom metadata:** it is plain text in source control and change sets.
- **Custom labels:** they are plain text and readable by every user.
- **Static resources, text fields or debug logs:** all of these are plain text.

## Metadata

The project has no existing credentials or permission sets, so these are new.

`force-app/main/default/externalCredentials/ERP.externalCredential-meta.xml`
```xml
<?xml version="1.0" encoding="UTF-8"?>
<ExternalCredential xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>ERP</label>
    <authenticationProtocol>Custom</authenticationProtocol>
    <externalCredentialParameters>
        <parameterName>ERP_Principal</parameterName>
        <parameterType>NamedPrincipal</parameterType>
        <sequenceNumber>1</sequenceNumber>
    </externalCredentialParameters>
    <externalCredentialParameters>
        <parameterName>X-API-Key</parameterName>
        <parameterType>AuthHeader</parameterType>
        <parameterValue>{!$Credential.ERP.ApiKey}</parameterValue>
        <sequenceNumber>1</sequenceNumber>
    </externalCredentialParameters>
</ExternalCredential>
```


## Steps

1. **Deploy the metadata to the sandbox.** It contains no key.
2. **Enter the key in Setup.** Go to Setup → Named Credentials → External Credentials → ERP → principal `ERP_Principal` → add an authentication parameter named `ApiKey` and paste the key. Repeat in each org. The key never goes in source control.
3. **Set the real URL** on the Named Credential. I used the placeholder `https://erp.example.com`.
4. **Assign `ERP_Callout`** to whoever runs the callout. That is the integration user, or the users who trigger it. Without it, the callout fails with an authorization error.
5. **Call it from Apex:**
   ```apex
   req.setEndpoint('callout:ERP/v1/orders');
   ```
   Don't log request headers.

If the sandbox calls a test ERP, keep the same credential name and change only the URL and key in that org.

## Assumptions

- **Header name:** the key is sent as an `X-API-Key` header. If your ERP expects something else, such as `Authorization` or a different header name, change `parameterName`.
- **Formula in header:** if the callout sends the literal `{!$Credential.ERP.ApiKey}` instead of the key, turn on **Allow Formulas in HTTP Header** on the Named Credential. I couldn't confirm this against the docs, so test it in the sandbox first.
- **Callout code:** I haven't written any Apex for the callout yet. If you want it, I'll write it as `with sharing`, with a test class that mocks the callout and runs as a user who has only `ERP_Callout`.
