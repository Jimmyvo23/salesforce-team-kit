# S5: API key (with-skill)

Store it in a **Named Credential backed by an External Credential**. Apex then calls `callout:ERP/...` and never sees the key. I couldn't write files in this session, so the three metadata files are below, each with its path. They use `apiVersion` 62.0 from `sfdx-project.json`, and `https://erp.example.com` is a placeholder URL.

**1. External credential**

`force-app/main/default/externalCredentials/ERP.externalCredential-meta.xml`
```xml
<?xml version="1.0" encoding="UTF-8"?>
<ExternalCredential xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>ERP</label>
    <authenticationProtocol>Custom</authenticationProtocol>
    <externalCredentialParameters>
        <parameterName>ERP_Principal</parameterName>
        <parameterType>NamedPrincipal</parameterType>
        <sequenceNumber>1</sequenceNumber>
    </externalCredentialParameters>
    <externalCredentialParameters>
        <parameterName>X-API-Key</parameterName>
        <parameterType>AuthHeader</parameterType>
        <parameterValue>{!$Credential.ERP.ApiKey}</parameterValue>
        <sequenceNumber>1</sequenceNumber>
    </externalCredentialParameters>
</ExternalCredential>
```
This assumes the ERP expects the key in an `X-API-Key` header. If it uses a different header name, change `parameterName`.

**2. Named credential**

`force-app/main/default/namedCredentials/ERP.namedCredential-meta.xml`
```xml
<?xml version="1.0" encoding="UTF-8"?>
<NamedCredential xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>ERP</label>
    <namedCredentialType>SecuredEndpoint</namedCredentialType>
    <namedCredentialParameters>
        <parameterName>Url</parameterName>
        <parameterType>Url</parameterType>
        <parameterValue>https://erp.example.com</parameterValue>
    </namedCredentialParameters>
    <namedCredentialParameters>
        <parameterName>ExternalCredential</parameterName>
        <parameterType>Authentication</parameterType>
        <externalCredential>ERP</externalCredential>
    </namedCredentialParameters>
    <generateAuthorizationHeader>false</generateAuthorizationHeader>
</NamedCredential>
```

**3. Permission set for whoever runs the callout**

`force-app/main/default/permissionsets/ERP_Callout.permissionset-meta.xml`
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PermissionSet xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>ERP Callout</label>
    <description>Lets the assigned users run callouts that use the ERP Named Credential.</description>
    <hasActivationRequired>false</hasActivationRequired>
    <externalCredentialPrincipalAccesses>
        <enabled>true</enabled>
        <externalCredentialPrincipal>ERP-ERP_Principal</externalCredentialPrincipal>
    </externalCredentialPrincipalAccesses>
</PermissionSet>
```
Assign it to the integration user, or to the users or permission set group whose actions trigger the callout.

**4. Enter the key in Setup, in each org**

Go to Setup → Named Credentials → External Credentials → ERP → the `ERP_Principal` principal. Add the authentication parameter `ApiKey` and paste the key. Salesforce stores it encrypted, and it never appears in the metadata or source control. Repeat this in each sandbox, using the sandbox ERP's key. The Named Credential name stays `ERP`, so only the URL and key change per org.

**5. Apex**
```apex
HttpRequest req = new HttpRequest();
req.setEndpoint('callout:ERP/v1/orders');
req.setMethod('GET');
```
Don't log request headers.

**Where not to put the key**
- **Apex code or constants:** they end up in source control and every sandbox.
- **Custom settings:** every profile can read them, including the guest user.
- **Custom metadata:** it's stored and deployed as plain text.
- **Custom labels:** they're plain text and readable by every user.
- **Static resources, text fields and debug logs:** all plain text.
