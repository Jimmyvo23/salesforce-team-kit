### 2. Guest sharing rule: the only way records reach guests (Read only)
`force-app/main/default/sharingRules/Product2.sharingRules-meta.xml`

```xml
<?xml version="1.0" encoding="UTF-8"?>
<SharingRules xmlns="http://soap.sforce.com/2006/04/metadata">
    <sharingGuestRules>
        <fullName>Active_Products_For_Site_Guests</fullName>
        <accessLevel>Read</accessLevel>
        <label>Active products for site guests</label>
        <sharedTo>
            <guestUser>CHANGE_ME_SiteGuestNickname</guestUser>
        </sharedTo>
        <criteriaItems>
            <field>IsActive</field>
            <operation>equals</operation>
            <value>True</value>
        </criteriaItems>
        <includeHVUOwnedRecords>false</includeHVUOwnedRecords>
    </sharingGuestRules>
</SharingRules>
```

### Guest safety
1. **Don't give guests Edit** (or Delete, View All, Modify All) on Product2, even if asked later. Read is the most a guest gets.
2. **Don't use `without sharing` Apex or system-mode queries to show guests more.** Any Apex the site calls is `with sharing` and `WITH USER_MODE`.
3. **Records guests create are owned by the site's default internal owner.** That setting is in the site's Preferences under secure guest user settings. Check that an active internal user is set and that it isn't one person for everything. This doesn't affect Product2 reads, but it matters if you add forms later.
