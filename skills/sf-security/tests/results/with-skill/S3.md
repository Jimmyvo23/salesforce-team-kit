## The problem

Your original line concatenates `searchTerm` straight into the query string, which is SOQL injection. A value like `x' OR Name != '` changes the query itself. `Database.query` also runs in system mode at API 62.0, so it skips object and field permissions.

## Fix

The query has no dynamic parts, so a static query with a bind variable is enough.

`force-app/main/default/classes/AccountSearchController.cls`
```apex
public with sharing class AccountSearchController {
    @AuraEnabled(cacheable=true)
    public static List<Account> search(String searchTerm) {
        if (String.isBlank(searchTerm) || searchTerm.trim().length() < 2) {
            return new List<Account>();
        }
        // Bind variable: the input is data, never part of the query text.
        String pattern = '%' + searchTerm.trim() + '%';
        return [
            SELECT Id, Name
            FROM Account
            WHERE Name LIKE :pattern
            WITH USER_MODE
            ORDER BY Name
            LIMIT 50
        ];
    }
}
```

- **Bind variable:** `:pattern` makes the input data, so quotes in it are harmless.
- **`WITH USER_MODE`:** this enforces object permissions, field-level security and sharing. `with sharing` on its own only enforces sharing.
- **Guards:** a blank or one-character term returns nothing, and `LIMIT 50` caps the result.
- **Wildcards:** a user's own `%` and `_` still act as wildcards in the `LIKE`. That's usually fine for search.

If you need dynamic field names or sort order, use `Database.queryWithBinds(soql, binds, AccessLevel.USER_MODE)`. Check the field names against an allow-list first, because they can't be bound.

## Supporting files

Create each class's `-meta.xml` with `<apiVersion>62.0</apiVersion>` and `<status>Active</status>`: `AccountSearchController.cls-meta.xml` and `AccountSearchControllerTest.cls-meta.xml`.

**`force-app/main/default/permissionsets/Account_Search.permissionset-meta.xml`** is read-only. It gives Read on Account plus access to the class. `Name` is a required field, so it needs no field permission.
```xml
<?xml version="1.0" encoding="UTF-8"?>
<PermissionSet xmlns="http://soap.sforce.com/2006/04/metadata">
    <label>Account Search</label>
    <hasActivationRequired>false</hasActivationRequired>
    <classAccesses>
        <apexClass>AccountSearchController</apexClass>
        <enabled>true</enabled>
    </classAccesses>
    <objectPermissions>
        <allowCreate>false</allowCreate>
        <allowDelete>false</allowDelete>
        <allowEdit>false</allowEdit>
        <allowRead>true</allowRead>
        <modifyAllRecords>false</modifyAllRecords>
        <object>Account</object>
        <viewAllRecords>false</viewAllRecords>
    </objectPermissions>
</PermissionSet>
```

**`force-app/main/default/classes/AccountSearchControllerTest.cls`**
```apex
@IsTest
private class AccountSearchControllerTest {
    private static User makeUser(String profileName, String permSetName) {
        User u;
        System.runAs(new User(Id = UserInfo.getUserId())) {   // avoids MIXED_DML_OPERATION
            Profile p = [SELECT Id FROM Profile WHERE Name = :profileName WITH SYSTEM_MODE];
            u = new User(
                Alias = 'sectest', Email = 'sectest@example.com', LastName = 'Test',
                Username = 'sectest' + DateTime.now().getTime() + '@example.com',
                ProfileId = p.Id, EmailEncodingKey = 'UTF-8', LanguageLocaleKey = 'en_US',
                LocaleSidKey = 'en_US', TimeZoneSidKey = 'America/Los_Angeles');
            insert as system u;
            if (permSetName != null) {
                PermissionSet ps = [SELECT Id FROM PermissionSet WHERE Name = :permSetName WITH SYSTEM_MODE];
                insert as system new PermissionSetAssignment(AssigneeId = u.Id, PermissionSetId = ps.Id);
            }
        }
        return u;
    }

    @IsTest
    static void findsMatchingAccountsForUserWithAccess() {
        User u = makeUser('Minimum Access - Salesforce', 'Account_Search');
        insert as system new List<Account>{
            new Account(Name = 'Acme Corp', OwnerId = u.Id),
            new Account(Name = 'Globex', OwnerId = u.Id)
        };
        System.runAs(u) {
            Test.startTest();
            List<Account> rows = AccountSearchController.search('cme');
            Test.stopTest();
            Assert.areEqual(1, rows.size(), 'Only Acme should match');
            Assert.areEqual('Acme Corp', rows[0].Name, 'Name should be returned');
        }
    }

    @IsTest
    static void injectionAttemptIsTreatedAsData() {
        User u = makeUser('Minimum Access - Salesforce', 'Account_Search');
        insert as system new Account(Name = 'O\'Brien Ltd', OwnerId = u.Id);
        insert as system new Account(Name = 'Other', OwnerId = u.Id);
        System.runAs(u) {
            Assert.areEqual(1, AccountSearchController.search('O\'Brien').size(), 'Quote is just text');
            Assert.areEqual(0, AccountSearchController.search('x\' OR Name != \'').size(), 'Injection matches nothing');
        }
    }

    @IsTest
    static void shortOrBlankTermReturnsNothing() {
        Assert.areEqual(0, AccountSearchController.search(null).size(), 'null');
        Assert.areEqual(0, AccountSearchController.search(' a ').size(), 'too short');
    }

    @IsTest
    static void failsForUserWithoutAccountAccess() {
        User u = makeUser('Minimum Access - Salesforce', null);
        System.runAs(u) {
            try {
                AccountSearchController.search('Acme');
                Assert.fail('Expected a QueryException for a user without Account access');
            } catch (QueryException e) {
                Assert.isTrue(e.getMessage() != null, 'Access error expected');
            }
        }
    }
}
```

## Assumptions

- **Method shape:** I made this an `@AuraEnabled` method for an LWC, with only `Id` and `Name` returned. If your caller isn't an LWC, drop the annotation. If it needs more fields, add them to the `SELECT`.
- **Profile name:** the tests use the `Minimum Access - Salesforce` profile. Confirm that name in your sandbox, because profile names differ between orgs.
- **Permissions:** assign `Account_Search` to the people who use the search, or add it to their permission set group. For edit access, you'd set `allowEdit` to `true`, but search doesn't need it.

Run the tests in the sandbox. This change should go to production only through your usual change set process.
