## What was wrong

Your line has a **SOQL injection** hole. `searchTerm` goes straight into the query text, so input like `%' OR Name != '` changes the query. It also runs without CRUD or FLS checks, because API 62.0 defaults to system mode. It has no `LIMIT` either.

The fix is a bind variable plus `WITH USER_MODE`. There's no dynamic field or object name, so a static query is enough and `Database.query` isn't needed.

I read `sourceApiVersion` from `sfdx-project.json`, which is 62.0. I didn't find your snippet in the repo, so I wrote it as a new class.

### `force-app/main/default/classes/AccountSearchController.cls`
```apex
public with sharing class AccountSearchController {
    @AuraEnabled(cacheable=true)
    public static List<Account> search(String searchTerm) {
        if (String.isBlank(searchTerm) || searchTerm.trim().length() < 2) {
            return new List<Account>();
        }
        // Bind variable: the input is data, never part of the query text.
        String pattern = '%' + searchTerm.trim() + '%';
        return [
            SELECT Id, Name
            FROM Account
            WHERE Name LIKE :pattern
            WITH USER_MODE
            ORDER BY Name
            LIMIT 50
        ];
    }
}
```

## Assumptions and notes
- **Fields:** it returns only `Id` and `Name`, which is what your query selected. Tell me if the UI needs more.
- **Search term:** it must be at least 2 characters, and the result is capped at 50 rows. Change either in the class.
- **Wildcards:** a user's own `%` or `_` still works as a wildcard inside `LIKE`. That's usually fine for search.
- **Permissions:** user mode also enforces sharing. Anyone calling this needs Read on Account (and Account.Name) and Apex class access to `AccountSearchController`, both from a permission set. I didn't edit any profile.
