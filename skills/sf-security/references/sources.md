# Sources

On 2026-10-19, developer.salesforce.com returned HTTP 403 to WebFetch and curl, and help.salesforce.com pages render only with JavaScript. The Security Implementation Guide PDF now redirects to a help.salesforce.com page, and there is no LWC PDF or general Experience Cloud PDF (`salesforce_lwc_dev_guide.pdf`, `salesforce_communities_implementation.pdf` and similar names return 404). So the Apex Developer Guide, Metadata API Developer Guide, Object Reference and SOQL and SOSL Reference were read in their official PDF editions (all v68.0, Winter '27), and help topics were checked through WebSearch limited to help.salesforce.com and developer.salesforce.com.

## Read in the official PDFs

- CRUD/FLS: user mode is the default at API 67.0 and later and system mode at 66.0 and earlier; `WITH SECURITY_ENFORCED` is not allowed at 67.0 and later; `with sharing` doesn't enforce permissions or FLS: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Apex Security and Sharing Model", "Enforce Sharing Rules", "Enforce Object and Field Permissions", Versioned Behavior Changes, PDF p.219–223) (checked 2026-10-19)
- Sharing and access modes: a user-mode operation always respects sharing; in system mode the sharing keyword of the calling class decides record access; `WITH USER_MODE`, `as user`, `AccessLevel`, `queryWithBinds` requires the access level: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Set an Access Mode for Database Operations", PDF p.223–225) (checked 2026-10-19)
- Sharing defaults by API version (classes without a keyword run with sharing at 67.0 and later; older rules for 66.0 and earlier): https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Apex Security and Sharing Model", Versioned Behavior Changes, PDF p.220) (checked 2026-10-19)
- `Security.stripInaccessible`, `SObjectAccessDecision`, `AccessType`: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Enforce Security with the stripInaccessible Method") (checked 2026-10-19)
- SOQL injection, bind variables, `Database.queryWithBinds`, `escapeSingleQuotes`: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Dynamic SOQL", "SOQL Injection", PDF p.214–216; "Security Tips", PDF p.250) (checked 2026-10-19)
- `System.runAs` enforces the user's sharing, object and field permissions; mixed DML in tests (User, PermissionSetAssignment) must run inside `System.runAs`; permission set groups in tests: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Using the runAs Method"; "Mixed DML Operations in Test Methods", PDF p.169–170; "Testing Permission Set Groups", PDF p.519) (checked 2026-10-19)
- Apex class access through permission sets: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Class Security", PDF p.230–231) (checked 2026-10-19)
- Custom settings are readable by all profiles, including the guest user, unless protected inside a managed package; use named credentials for secrets: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Custom Settings", PDF p.251) (checked 2026-10-19)
- Named Credentials as callout endpoints (`callout:Name/path`, the external credential holds authentication): https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Named Credentials as Callout Endpoints", PDF p.624–628) (checked 2026-10-19)
- Apex managed sharing can't grant access to unauthenticated guest users: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Understanding Apex Managed Sharing") (checked 2026-10-19)
- SOQL clause order (`WITH` after `WHERE`, before `GROUP BY` / `ORDER BY` / `LIMIT`) and `FIELDS()`: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_soql_sosl.pdf ("SOQL SELECT Syntax", "FIELDS()") (checked 2026-10-19)
- Metadata: PermissionSet `fieldPermissions` (required-field permissions can't be deployed), `externalCredentialPrincipalAccesses` (API 59.0+); PermissionSetGroup and MutingPermissionSet; SharingRules `sharingGuestRules` (Read only, `sharedTo.guestUser`); SharingSettings (guest org-wide defaults always Private from API 50.0); ExternalCredential (`Custom` protocol, `AuthHeader` parameter as a formula, credentials encrypted); NamedCredential (`SecuredEndpoint`, `Url`, `Authentication`): https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf (Metadata API Developer Guide v68.0) (checked 2026-10-19)
- Product2 supports sharing rules (Product2OwnerSharingRule, API 50.0): https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/object_reference.pdf ("Product2") (checked 2026-10-19)

- Secure guest users (Winter '27, last updated 2026-07-22): guest records get a default owner, set at Setup > Digital Experiences > All Sites > Workspaces > Administration > Preferences; don't use the default owner as the only assignment method, use assignment rules, processes or triggers to route records to users or queues; more than one owner; queues where possible: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/communities_secure_guest_users.pdf ("Assign Records Created by Guest Users to a Default User in the Org", "Best Practices and Considerations for Using the Guest Record Default Owner", PDF p.20) (checked 2026-10-19)
- At API 67.0 and later an operation with no access mode runs in user mode, which reapplies sharing and overrides a `without sharing` context: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Use the with sharing, without sharing, and inherited sharing Keywords", trigger example, PDF p.94–95; "Set an Access Mode for Database Operations" note, PDF p.223) (checked 2026-10-19)
