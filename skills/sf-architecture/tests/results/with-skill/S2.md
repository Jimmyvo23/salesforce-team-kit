## 3. Recommendation (provisional): before-save record-triggered flow
This is the right tool because the change sets a field on the same record being saved.
- **Why it beats the alternatives:**
  - A before-save flow needs no extra DML and no second save.
  - An after-save flow or Apex trigger would re-run the save order on the same record.
  - Apex adds code and tests for no gain.
  - A formula field would also work if the date were display-only. But you said to set it on save, and a stored field can be reported on, filtered, and edited by users.
- **Limits of before-save:** it can only change `$Record`. It can't touch other records, and this change doesn't need that.
- **Rejected:** Workflow Rule and Process Builder are retired.
- **Run context:** the flow runs in system context without sharing. It only writes a field on the record the user is already saving, so this is fine.

## 4. Design details
- **Object and trigger:** Opportunity, "A record is created or updated", before-save, with an explicit `TriggerOrder` once the inventory is back.
- **Entry condition:**
  - Use `NOT(ISBLANK({!$Record.CloseDate}) )` AND (`ISNEW()` OR `ISCHANGED({!$Record.CloseDate})`).
  - Set the run option to "Only when a record is updated to meet the condition requirements", so it doesn't fire on every save.
- **Logic:** Assignment `{!$Record.Next_Step_Date__c} = {!$Record.CloseDate} - 7`. Date minus a number gives a Date. There's no Update Records element and no DML.
- **Idempotent:** re-saving with the same `CloseDate` doesn't re-trigger it, and the result is the same either way.
- **Bulk:** the flow bulkifies automatically. With 200 Opportunities in one chunk there are no queries and no DML, and each record is computed independently.
- **Recursion and order:** it runs first in the save order, before before-triggers and validation rules. It writes no other record, so there's no loop and no other object's automation fires. Validation rules on Opportunity will see the new date.
- **Failure handling and limits:** no callouts and no async work. The flow can't fail on a blank `CloseDate`, because the entry condition excludes it. (`CloseDate` is required on Opportunity anyway.)

## 5. Test cases for `uat`
1. **Create:** an Opportunity with `CloseDate` 2026-12-31 gets `Next_Step_Date__c` 2026-12-24.
2. **Change:** updating `CloseDate` recalculates the date.
3. **Not newly met:** editing another field such as Amount leaves a manually edited `Next_Step_Date__c` untouched.
4. **Already set:** saving with the same `CloseDate` doesn't change anything.
5. **Bulk:** insert and update 200 Opportunities in one go, and check every record's date.
6. **Month and year boundary:** `CloseDate` 2026-01-03 gives 2025-12-27.
7. **Other automation:** the existing flows and triggers still pass after this one is added.
