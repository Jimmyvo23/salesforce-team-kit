## 3. Recommendation
**Preferred option: a formula field, if it fits.** A score that is only a calculation for display is the textbook formula case.

**The risk is compile size.** The limit is 15,000 bytes compiled (check the current "Formula Field Limits and Restrictions" page). A formula's compiled size includes the compiled size of every formula it references. Fifteen formula inputs, each with its own logic, are likely to exceed the limit. Splitting the score into helper formulas does not reduce compile size. It only helps with the 3,900-character limit.

**Test it first.** Build `Health_Score__c` as a formula in `uat` and see whether it saves. If it does, ship the formula. It needs no automation and is always current.

**Fallback if it doesn't compile:** make `Health_Score__c` a stored Number field set by a before-save record-triggered flow on Account.
- It only sets a field on the same record, so before-save is right. It needs no extra DML and no second save.
- Apex would add code and tests for no gain.
- An after-save flow would re-run the save order for no reason.
- A stored value can also be indexed and filtered.

**If the inventory shows an Apex trigger on Account:** the logic goes in that trigger's handler, not in a flow, and never in a second trigger.

**Staleness caveat for the stored field:**
- If any input uses `TODAY()`/`NOW()` or reads other records, the stored value goes stale. In that case add a scheduled flow or batch to recalculate it.
- Before relying on the flow, confirm in `uat` that the input formulas return current values in the before-save context.

## 4. Fallback design details
- **Entry condition:** the flow runs on create and update, but only when one of the underlying inputs changed (an `ISCHANGED` condition on each source field). The write is idempotent because it recomputes the same value from the same inputs.
- **Bulk:** the flow runs on up to 200 records per chunk with no queries or DML, so it is bulk-safe.
- **Order of execution:** it runs in the before-save flow step, ahead of before triggers and validation rules. It writes no other records, so nothing re-fires and there is no loop.
- **Flow order:** give it an explicit `TriggerOrder` that fits whatever the inventory shows.

## 5. Failure handling and limits
- There are no callouts and no related-record writes, so there is no retry logic to design.
- The limits that matter are the formula compile size (15,000 bytes) and the 3,900-character formula limit.

## 6. Sandbox tests
- **Bulk:** 200 Accounts inserted or updated at once all get a correct score.
- **Already set:** re-saving an Account with unchanged inputs leaves the score unchanged.
- **Condition not newly met:** editing a field that isn't an input doesn't re-run the calculation.
- **Boundaries:** blank and null inputs, and the minimum and maximum scores.
- **Staleness:** if any input is time-based, check that the scheduled recalculation updates the score.
