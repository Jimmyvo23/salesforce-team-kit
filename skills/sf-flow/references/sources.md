# Sources

On 2026-10-16, developer.salesforce.com returned HTTP 403 to WebFetch and curl, and help.salesforce.com pages render only with JavaScript. Salesforce publishes no PDF edition of the Flow help (`salesforce_flows.pdf`, `salesforce_flow_ref.pdf`, `salesforce_automate_your_business_processes.pdf` and similar names return 404). So the Metadata API and Apex guides were read in their official PDF editions, and the Flow help topics were checked through WebSearch, limited to help.salesforce.com and developer.salesforce.com.

## Read in the official PDFs

- Flow metadata: `status` values (Active, Draft, Obsolete, InvalidDraft), `runInMode` values (DefaultMode, SystemModeWithSharing, SystemModeWithoutSharing, and UserMode at API 68.0 and later), `start.triggerType` (RecordBeforeSave, RecordAfterSave, RecordBeforeDelete, Scheduled, PlatformEvent and others), `recordTriggerType`, `doesRequireRecordChangedToMeetCriteria`, `filterFormula`, `faultConnector`; deploying changes to an active flow in a sandbox creates a new active version; inactive versions without paused interviews can be deleted; FlowDefinition `activeVersionNumber` overrides `status`; don't edit retrieved Process Builder metadata: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf ("Flow", "FlowDefinition", Metadata API Developer Guide v68.0, Winter '27, last updated 2026-10-16) (checked 2026-10-16)
- Flow tests: FlowTest metadata for record-triggered, autolaunched and Data Cloud-triggered flows, API 55.0 and later; FlowTestParameter type `ScheduledPath` (API 56.0 and later) tests scheduled paths: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/api_meta.pdf ("FlowTest") (checked 2026-10-16)
- Invocable Apex: `@InvocableMethod` rules (static, public or global, outer class, one per class, one list parameter), outputs must match inputs in size and order for bulk execution in record-triggered flows, return failures in an output object: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("InvocableMethod Annotation", "InvocableMethod Considerations", Apex Developer Guide v68.0) (checked 2026-10-16)
- Email from Apex and flows is sent only when the transaction commits ("The email is not sent until the Apex transaction is committed"), so a Custom Error rollback drops it: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Outbound Email") (checked 2026-10-16)
- Governor limits shared by the transaction (100 SOQL, 150 DML statements, 10,000 DML rows): https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/salesforce_apex_developer_guide.pdf ("Execution Governors and Limits") (checked 2026-10-16)
- Platform events: Publish Immediately messages are published even if the transaction rolls back; platform event-triggered flows can't call subflows: https://resources.docs.salesforce.com/latest/latest/en-us/sfdc/pdf/platform_events.pdf (Platform Events Developer Guide v68.0) (checked 2026-10-16)

## Points where sources differ

- Flow tests: older release notes say tests cover only create and update triggers. The current help page also mentions delete triggers. Both agree that Run Asynchronously paths aren't tested. Scheduled paths can be tested (FlowTestParameter type ScheduledPath, API 56.0 and later). The skill doesn't claim delete support.
