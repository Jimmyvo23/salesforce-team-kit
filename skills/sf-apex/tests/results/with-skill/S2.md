## Setup in the sandbox

- **Named Credential `ERP`:** URL `https://erp.example.com`, with an External Credential for authentication. The code calls `callout:ERP/api/orders`, so the URL and secrets never appear in Apex. Grant the External Credential principal to the users who save Orders through a permission set.
- **Two new text fields on Order:** `ERP_Sync_Status__c` (length 20) and `ERP_Last_Error__c` (length 255). Each needs its own `field-meta.xml` under `objects/Order/fields/`. Give the running users edit access to both, because the DML is `as user`.

## Code

**`triggers/OrderTrigger.trigger`** (add a `-meta.xml` with apiVersion 62.0, status Active)
```apex
trigger OrderTrigger on Order (after insert, after update) {
    OrderTriggerHandler.afterSave(Trigger.new, Trigger.oldMap);
}
```

**`classes/OrderTriggerHandler.cls`**
```apex
public with sharing class OrderTriggerHandler {
    public static void afterSave(List<Order> orders, Map<Id, Order> oldMap) {
        Set<Id> ids = new Set<Id>();
        for (Order o : orders) {
            // Send on insert and on a real Status change. The job only writes the ERP_* fields,
            // so its own update of Order does not match this filter and cannot loop.
            Boolean send = oldMap == null || o.Status != oldMap.get(o.Id).Status;
            if (send) {
                ids.add(o.Id);
            }
        }
        if (!ids.isEmpty()) {
            System.enqueueJob(new OrderErpSyncJob(ids));   // once per transaction
        }
    }
}
```

**`classes/OrderErpSyncJob.cls`**
```apex
public with sharing class OrderErpSyncJob implements Queueable, Database.AllowsCallouts {
    private static final Integer MAX_PER_JOB = 50;      // stays under 100 callouts and 120 s per job
    @TestVisible private static Boolean chainRemaining = true;   // tests switch chaining off: keeps the test to one job

    private final Set<Id> orderIds;

    public OrderErpSyncJob(Set<Id> orderIds) {
        this.orderIds = orderIds;
    }

    public void execute(QueueableContext ctx) {
        Set<Id> batch = new Set<Id>();
        Set<Id> rest = new Set<Id>();
        for (Id i : orderIds) {
            if (batch.size() < MAX_PER_JOB) {
                batch.add(i);
            } else {
                rest.add(i);
            }
        }

        List<Order> results = new List<Order>();
        for (Order o : [SELECT Id, OrderNumber, Status, TotalAmount, AccountId, EffectiveDate
                        FROM Order WHERE Id IN :batch WITH USER_MODE]) {
            results.add(OrderErpService.send(o));       // callouts first, no DML yet
        }
        update as user results;                          // then one DML with the outcomes

        if (!rest.isEmpty() && chainRemaining) {
            System.enqueueJob(new OrderErpSyncJob(rest));
        }
    }
}
```

**`classes/OrderErpService.cls`**
```apex
public with sharing class OrderErpService {
    // The Named Credential "ERP" holds https://erp.example.com and the authentication.
    @TestVisible private static final String ENDPOINT = 'callout:ERP/api/orders';

    /** Posts one Order. Makes the callout only; returns an Order carrying the outcome for the caller to save. */
    public static Order send(Order o) {
        HttpRequest req = new HttpRequest();
        req.setEndpoint(ENDPOINT);
        req.setMethod('POST');
        req.setHeader('Content-Type', 'application/json');
        req.setTimeout(20000);
        req.setBody(JSON.serialize(new Map<String, Object>{
            'salesforceId' => o.Id,
            'orderNumber' => o.OrderNumber,
            'accountId' => o.AccountId,
            'status' => o.Status,
            'effectiveDate' => o.EffectiveDate,
            'total' => o.TotalAmount
        }));

        Order result = new Order(Id = o.Id);
        try {
            HttpResponse res = new Http().send(req);
            Boolean ok = res.getStatusCode() >= 200 && res.getStatusCode() < 300;
            result.ERP_Sync_Status__c = ok ? 'Sent' : 'Failed';
            result.ERP_Last_Error__c = ok ? null : (res.getStatusCode() + ' ' + res.getBody()).left(255);
        } catch (CalloutException e) {                   // timeout or connection error
            result.ERP_Sync_Status__c = 'Failed';
            result.ERP_Last_Error__c = e.getMessage().left(255);
        }
        return result;
    }
}
```

## Things to know

- **When it sends:** on insert and whenever `Status` changes. If you want a different trigger condition, such as only when the Order is activated, change that one line in the handler.
- **No loop:** the job writes only the `ERP_*` fields, so its update never matches the Status filter.
- **200 Orders:** the trigger enqueues one job. Each job sends 50 Orders and chains a job for the rest. Chained jobs aren't tested; the 200-record test turns chaining off and asserts the first 50 only.
- **Failures are recorded, not retried:** any non-2xx response or timeout sets `Failed` and stores the error. There is no automatic retry yet. A scheduled job could re-send `Failed` Orders with 5xx errors or timeouts, with a retry cap. Tell me if you want that.
- **Orders saved from async code:** a trigger that fires inside a Queueable or Batch can enqueue only one job, and the handler doesn't guard against that. If Orders get saved from async code, switch to setting a `Pending` status that a scheduled job picks up.
- **User mode:** the job's `update as user` fails if the user who saved the Order can't edit the two ERP fields. Say so if the sync status should be written for every user. I would then change that one statement to `as system`, with a comment.
- **Test data:** `OrderTestDataFactory` assumes `Draft` and `Activated` are valid Order statuses and that standard Orders are enabled. Adjust it for any required fields or validation rules in your org.
