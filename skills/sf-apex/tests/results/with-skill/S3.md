**Two assumptions to confirm**
- **Field:** you didn't say which field or what the calculation is. I assumed a new `Account.Score__c` number field. `AccountScoring.score()` holds a **placeholder formula** (revenue and headcount points, capped at 100). Replace it with your real rule.
- **System mode:** the batch is `without sharing` and runs in system mode on purpose, so it updates all 3 million Accounts regardless of who scheduled it. Schedule it as an integration user. If it should respect the scheduling user's access instead, I'll switch it to `with sharing` and user mode.

**Design**
- **Batch Apex:** 3 million rows is too many for one transaction. `start` returns a QueryLocator, which can hold up to 50 million rows.
- **Scope:** `execute` runs 200 rows at a time. It only updates rows whose value changed, and does one bulk `Database.update` per scope.
- **Failures:** the update uses partial success, so one bad row doesn't roll back the other 199. Failures are counted and logged in `finish`.
- **Schedulable:** the Schedulable only calls `executeBatch`.
- **Cheaper nightly runs:** if the score only depends on a few fields, add a filter to the `start` query so you don't scan every Account each night.

**`force-app/main/default/classes/AccountScoreBatch.cls`**
```apex
// Org-wide maintenance: runs without sharing and in system mode on purpose, so it
// recalculates every Account no matter who scheduled it. Schedule it as an integration user.
public without sharing class AccountScoreBatch implements Database.Batchable<SObject>, Database.Stateful {
    private Integer updated = 0;
    private Integer failed = 0;

    public Database.QueryLocator start(Database.BatchableContext bc) {
        return Database.getQueryLocator(
            'SELECT Id, AnnualRevenue, NumberOfEmployees, Score__c FROM Account',
            AccessLevel.SYSTEM_MODE);
    }

    public void execute(Database.BatchableContext bc, List<Account> scope) {
        List<Account> changed = new List<Account>();
        for (Account a : scope) {
            Decimal score = AccountScoring.score(a);
            if (a.Score__c != score) {          // skip unchanged rows: saves DML and trigger runs
                a.Score__c = score;
                changed.add(a);
            }
        }
        // Partial success: one bad row must not roll back the other 199.
        for (Database.SaveResult sr : Database.update(changed, false, AccessLevel.SYSTEM_MODE)) {
            if (sr.isSuccess()) {
                updated++;
            } else {
                failed++;
                System.debug(LoggingLevel.ERROR, 'Score update failed for ' + sr.getId() + ': ' + sr.getErrors()[0].getMessage());
            }
        }
    }

    public void finish(Database.BatchableContext bc) {
        System.debug('AccountScoreBatch finished. Updated: ' + updated + ', failed: ' + failed);
    }
}
```

@IsTest
private class AccountScoreBatchTest {
    private static List<Account> makeAccounts(Integer n, Decimal revenue, Integer employees, Decimal score) {
        List<Account> accts = new List<Account>();
        for (Integer i = 0; i < n; i++) {
            accts.add(new Account(Name = 'Score Test ' + i, AnnualRevenue = revenue,
                NumberOfEmployees = employees, Score__c = score));
        }
        return accts;
    }

    @IsTest
    static void scoringRule() {
        Assert.areEqual(0, AccountScoring.score(new Account()), 'Nulls score 0');
        Assert.areEqual(15, AccountScoring.score(new Account(AnnualRevenue = 10000000, NumberOfEmployees = 500)), 'Revenue plus size points');
        Assert.areEqual(100, AccountScoring.score(new Account(AnnualRevenue = 900000000)), 'Capped at 100');
    }

    @IsTest
    static void batchUpdatesScope200() {
        insert makeAccounts(200, 10000000, 500, null);

        Test.startTest();
        Database.executeBatch(new AccountScoreBatch(), 200);
        Test.stopTest();

        List<Account> result = [SELECT Score__c FROM Account];
        Assert.areEqual(200, result.size(), 'All accounts present');
        for (Account a : result) {
            Assert.areEqual(15, a.Score__c, 'Score recalculated');
        }
    }

    @IsTest
    static void alreadyCurrentScoresStayUnchanged() {
        insert makeAccounts(200, 10000000, 500, 15);

        Test.startTest();
        Database.executeBatch(new AccountScoreBatch(), 200);
        Test.stopTest();

        for (Account a : [SELECT Score__c FROM Account]) {
            Assert.areEqual(15, a.Score__c, 'Score still correct');
        }
    }

    @IsTest
    static void staleScoreIsCorrected() {
        insert makeAccounts(1, 3000000, 0, 99);

        Test.startTest();
        Database.executeBatch(new AccountScoreBatch(), 200);
        Test.stopTest();

        Assert.areEqual(3, [SELECT Score__c FROM Account LIMIT 1].Score__c, 'Stale value replaced');
    }

    @IsTest
    static void scheduleIsRegistered() {
        Test.startTest();
        System.schedule('Account score nightly test', '0 0 2 * * ?', new AccountScoreSchedule());
        Test.stopTest();

        Assert.areEqual(1, [SELECT COUNT() FROM CronTrigger WHERE CronJobDetail.Name = 'Account score nightly test'],
            'Schedule registered');
    }
}

**Notes**
- **"Already current" test:** it only asserts that the values stay correct. It doesn't prove that no DML happened.
- **Schedule test:** it checks that the job registers. It doesn't wait for the cron time, so the batch itself is covered by the other tests.
- **Org automation:** triggers and flows on Account will fire for every changed row. With 3 million rows that can be slow and can hit limits, so check what's active before the first full run.
- **Concurrency:** only 5 batch jobs can be queued or active at once, so check for overlap with other nightly jobs.
