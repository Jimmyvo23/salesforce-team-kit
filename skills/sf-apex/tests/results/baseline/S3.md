**Assumptions to change first:**
- You didn't name the field or the rule, so I used a placeholder field, `Account.Revenue_Tier__c`. It doesn't exist in this project. The rule is a stand-in that buckets `AnnualRevenue` into Enterprise, Mid-Market and SMB.
- Put your real rule in `calculate()`. Swap the field name in the SOQL, the update and the test.
- The batch is `without sharing`, because a system-wide recalculation shouldn't skip records the running user can't see.

**`AccountRecalcBatch.cls`**
```apex
public without sharing class AccountRecalcBatch implements Database.Batchable<SObject>, Database.Stateful {
    public static final Integer SCOPE_SIZE = 1000;

    private Integer processed = 0;
    private Integer updated = 0;
    private Integer failed = 0;

    public Database.QueryLocator start(Database.BatchableContext bc) {
        // QueryLocator is not subject to the 50k row limit, so it can cover ~3M records.
        return Database.getQueryLocator('SELECT Id, AnnualRevenue, Revenue_Tier__c FROM Account');
    }

    public void execute(Database.BatchableContext bc, List<Account> scope) {
        List<Account> changed = new List<Account>();
        for (Account acc : scope) {
            String newValue = calculate(acc);
            // Skip unchanged rows: avoids needless DML, triggers, and row-lock contention.
            if (acc.Revenue_Tier__c != newValue) {
                changed.add(new Account(Id = acc.Id, Revenue_Tier__c = newValue));
            }
        }
        processed += scope.size();
        if (changed.isEmpty()) return;

        // Partial success: one bad record (lock, validation) must not fail the other 999.
        for (Database.SaveResult r : Database.update(changed, false)) {
            if (r.isSuccess()) {
                updated++;
            } else {
                failed++;
                System.debug(LoggingLevel.ERROR, 'AccountRecalcBatch failed for ' + r.getId() + ': ' + r.getErrors()[0].getMessage());
            }
        }
    }

    public void finish(Database.BatchableContext bc) {
        System.debug('AccountRecalcBatch done. processed=' + processed + ' updated=' + updated + ' failed=' + failed);
    }

    /** Replace with the real business rule. Keep it pure (no SOQL/DML). */
    @TestVisible
    private static String calculate(Account acc) {
        if (acc.AnnualRevenue == null) return null;
        if (acc.AnnualRevenue >= 1000000) return 'Enterprise';
        return acc.AnnualRevenue >= 100000 ? 'Mid-Market' : 'SMB';
    }
}
```

**`AccountRecalcSchedulable.cls`**
```apex
public with sharing class AccountRecalcSchedulable implements Schedulable {
    public static final String JOB_NAME = 'Nightly Account Recalc';
    private static final String CRON_2AM_DAILY = '0 0 2 * * ?';

    public static Id schedule() {
        return System.schedule(JOB_NAME, CRON_2AM_DAILY, new AccountRecalcSchedulable());
    }

    public void execute(SchedulableContext sc) {
        Database.executeBatch(new AccountRecalcBatch(), AccountRecalcBatch.SCOPE_SIZE);
    }
}
```

**`AccountRecalcBatchTest.cls`**
```apex
@IsTest
private class AccountRecalcBatchTest {
    @IsTest
    static void recalculatesAccounts() {
        insert new List<Account>{
            new Account(Name = 'Big', AnnualRevenue = 5000000),
            new Account(Name = 'Mid', AnnualRevenue = 200000),
            new Account(Name = 'Small', AnnualRevenue = 10),
            new Account(Name = 'None')
        };
        Test.startTest();
        Database.executeBatch(new AccountRecalcBatch(), AccountRecalcBatch.SCOPE_SIZE);
        Test.stopTest();

        Map<String, Account> byName = new Map<String, Account>();
        for (Account a : [SELECT Name, Revenue_Tier__c FROM Account]) byName.put(a.Name, a);
        System.assertEquals('Enterprise', byName.get('Big').Revenue_Tier__c);
        System.assertEquals('Mid-Market', byName.get('Mid').Revenue_Tier__c);
        System.assertEquals('SMB', byName.get('Small').Revenue_Tier__c);
        System.assertEquals(null, byName.get('None').Revenue_Tier__c);
    }

    @IsTest
    static void schedulesNightlyJob() {
        Test.startTest();
        Id jobId = AccountRecalcSchedulable.schedule();
        Test.stopTest();
        System.assertEquals('0 0 2 * * ?', [SELECT CronExpression FROM CronTrigger WHERE Id = :jobId].CronExpression);
    }
}
```

Each class also needs a `.cls-meta.xml` file with `apiVersion` 62.0 and `status` Active, the same as `OpportunityService.cls-meta.xml`.

**Design choices:**
- **Scale:** The batch uses a `QueryLocator` with a scope of 1000, which is about 3,000 batches for 3M records. Only rows whose value actually changed are written, which usually cuts most of the DML on a nightly run.
- **Errors:** `Database.update(..., false)` lets the other records in a batch succeed when one fails. Failures are counted and logged in `finish`. For production you'll probably want a log object or an email there instead of `System.debug`.
- **Triggers and automation:** Check Account triggers, flows and validation rules before the first run. They will fire on every changed row. If the volume is a problem, a bypass flag is the usual fix.
- **Run time:** Expect hours on the first run, when most records change. Later runs should be much faster. Schedule it outside business hours, because a batch this size will compete for row locks.

**Deploying:** The project only has a `uat` sandbox alias, and you deploy to production yourself with change sets, so I'd run it in `uat` first. Run `AccountRecalcSchedulable.schedule();` once to register the nightly job. I haven't run the tests, since nothing could be deployed from here.
